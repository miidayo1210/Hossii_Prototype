# Hossiiからの挑戦状

## 質問・ミッション・スタンプカード機能仕様書

> **分類:** `[Core / Challenge / Mission / Question / Progress / Collection]`
> **文書番号:** 127
> **参加者向け名称:** Hossiiからの挑戦状
> **画面タイトル:** 学びを深める、Hossiiからの挑戦状！
> **管理者向け名称:** 質問・ミッション管理
> **ステータス:** 正本・調査反映済み（実装着手前）
> **対象:** スーパー管理者、スペース管理者、ログイン済み参加者（発行参加IDを含む）
> **初期表示モード:** スタンプカード
> **将来拡張:** ビンゴ、すごろく、クエストマップ、共同チャレンジ、修了証出力

# 1. 概要

「Hossiiからの挑戦状」は、スペース管理者またはスーパー管理者が、スペース内に質問やミッションを設置し、参加者が回答または行動を達成する機能である。

参加者が質問・ミッションの達成条件を満たすと、その参加者のスタンプカードに、さまざまな表情や姿をしたHossiiが付与される。

付与されたHossiiはアカウント全体の「Hossiiコレクション」に蓄積される。

一連の質問・ミッションは「挑戦状ストーリー」としてまとめられ、参加者は自分の回答、写真、達成した行動、取得したHossiiを「自分の軌跡」として振り返ることができる。

すべての必須項目を達成した場合は、完了演出と完了限定Hossiiを表示する。

---

# 2. 開発目的

これまでのHossiiは、参加者が自由に投稿し、想いや行動を共有することを中心としてきた。

本機能では、自由投稿に加えて、主催者や管理者が問いや行動のきっかけを用意できるようにする。

目的は、参加者を管理・評価することではなく、以下を実現することである。

* 行動を始めるきっかけをつくる
* 学びや気づきを記録する
* 途中経過を含めた積み重ねを可視化する
* 心理的安全性を保ちながら回答できる
* Hossiiを集める楽しさによって継続を促す
* 自分の回答や達成を、個人の軌跡として振り返る
* 誰かと同じストーリーに取り組む感覚をつくる

# 3. 用語定義

## 3.1 挑戦状

参加者向けに表示される、個別の質問またはミッションの総称。

## 3.2 質問

考え、感情、経験、気づきなどの入力を求めるもの。

例：

* 今日、一番印象に残ったことは？
* 今の気持ちに近いものを選んでください
* 次にやってみたいことは？

## 3.3 ミッション

特定の行動や実践を求めるもの。

例：

* 初めて会った人に話しかける
* 気になった場所の写真を撮る
* チームメンバーへ感謝を伝える

## 3.4 挑戦状ストーリー

複数の質問・ミッションをまとめた一連のパッケージ。

例：

* 下妻アカデミー第1章
* 今日の学びを見つける5つの挑戦状
* 石蔵を知る10の挑戦状
* 30日アクション

内部仕様上は `challenge_program` を仮称とする。

## 3.5 スタンプカード

挑戦状ストーリーの達成状況を、Hossiiスタンプの集合として表示する進捗UI。

## 3.6 Hossiiスタンプ

質問・ミッションを達成した時に付与される、さまざまな表情・ポーズ・装飾を持つHossii。

## 3.7 Hossiiコレクション

複数のスペースや挑戦状ストーリーを横断して、アカウントが取得したHossiiを一覧表示する機能。

## 3.8 自分の軌跡

参加者自身の回答、写真、選択内容、達成した行動、取得Hossii、おみくじ、開始日、完了日をまとめて表示する記録。

## 3.9 スペース管理者（参加者向け用語と現行実装の対応）

本仕様における表示名・役割名は「スペース管理者」とする。参加者向けUIにもこの名称を用いる。

現行実装上の対応は、次のとおりである。

* 本仕様におけるスペース管理者は、対象スペースが所属するコミュニティの管理者に対応する
* 権限判定の正本は、コミュニティ管理者の識別とスーパー管理者判定である
* 実装上の判定は、現行のスペース管理可否判定およびスペース所属コミュニティ管理者判定に対応する
* スペース所属レコード上の役割（メンバー／管理者など）は、本機能の一般管理権限判定には使用しない
* 将来、スペース固有の管理者が追加された場合は、本仕様の権限章を別途更新する

> **実装依存注記（参加者向けには露出しない）:**  
> 現行コード／DBでは、コミュニティ管理者の正本は `communities.admin_id`、スーパー管理者は JWT `app_metadata.role = 'super_admin'`、フロントの `canManageSpace` および DB の `is_space_community_admin` が対応する。`space_memberships.role` は本機能の一般管理権限には用いない。

## 3.10 発行参加ID

管理者がスペース向けに発行するログイン用アカウント。現行では通常の認証ユーザーとして扱われ、ゲストとは区別される。

挑戦状機能では、発行参加IDでログインした参加者もログイン済みアカウントとして扱う（詳細は 5.3）。

## 3.11 既存の `#card` スタンプとの区別

既存のスペース内 `#card` 画面に表示されるスタンプ機能は、投稿数などに基づく別機能である。

本仕様のスタンプカード（挑戦状ストーリーの達成進捗）とは、正本・進捗・UIを共有しない。

## 3.12 マイHossiiとの区別

既存のマイHossiiは、アカウントのHossii見た目設定である。

本仕様のHossiiコレクション（報酬付与履歴から導出する取得一覧）の正本にはしない。

# 5. 利用条件

## 5.1 ログイン

スタンプカード、Hossii取得、Hossiiコレクション、自分の軌跡を利用するには、ログイン済みアカウントを必須とする。

ゲスト参加者へのスタンプ付与や一時進捗保存は、初期実装では行わない。

## 5.2 未ログイン時

未ログイン状態で挑戦状を開いた場合は、以下を表示する。

> この挑戦状に取り組み、Hossiiを集めるにはログインが必要です。

その後、以下の導線を表示する。

* ログイン
* 新規登録

ログイン完了後は、元の挑戦状へ戻る。

## 5.3 発行参加ID

発行参加IDでログインした参加者も、認証済みアカウントとして扱う。

* 対象スペースに所属し、挑戦状ストーリーの対象者に含まれる場合は利用可能とする
* スタンプ、回答、軌跡、Hossiiコレクションは、当該認証ユーザーに紐づく
* 通常アカウントとの統合、アカウントマージ、報酬引き継ぎは今回のMVP対象外とする（将来対応）

# 6. 権限

## 6.0 スペース管理者の現行実装上の定義

仕様上の名称は「スペース管理者」のままとする。

現行実装との対応は、用語定義 3.9 および次のとおりである。

* 本仕様におけるスペース管理者は、現行実装上、対象スペースが所属するコミュニティの管理者に対応する
* 権限判定の正本は、コミュニティ管理者識別とスーパー管理者判定である
* 現行のスペース管理可否判定／スペース所属コミュニティ管理者判定に対応する
* スペース所属レコード上の役割は、本機能の一般管理権限判定には使用しない
* 将来スペース固有管理者が追加された場合は、権限仕様を別途更新する

コード名・テーブル名・関数名は実装依存情報として扱い、参加者向け用語には露出しない。

## 6.1 スーパー管理者

以下を実行できる。

* 全スペースの機能ON・OFF
* 全スペースの挑戦状ストーリー確認
* システム共通テンプレートの作成
* Hossiiスタンプ素材の登録・編集・停止
* レアリティ・抽選確率の管理
* おみくじ共通メッセージの管理
* 不具合対応に必要な監査情報の確認（ただし「自分だけ」回答への監査付き特別アクセスは、現行に存在しないため本仕様の前提にしない。詳細は 20.1）

## 6.2 スペース管理者

自身が管理するスペースにおいて、以下を実行できる。

* 挑戦状ストーリーの作成・編集・複製
* 質問・ミッションの作成
* 回答形式の設定
* 対象者の設定
* 公開範囲の設定
* Paneへの設置
* スタンプカードの表示設定
* 回答・進捗確認（「自分だけ」の回答を除く）
* 管理者承認
* ストーリーの公開・終了・アーカイブ

「自分だけ」に設定された回答は、通常のスペース管理者画面からも閲覧できない。

## 6.3 参加者

以下を実行できる。

* 対象となっている挑戦状ストーリーの閲覧
* 質問・ミッションへの回答
* 自分の回答の確認・修正
* スタンプカードの閲覧
* Hossiiコレクションの閲覧
* 自分の軌跡の閲覧

発行参加IDでログインした参加者も、対象者に含まれる場合は本節の権限を持つ。

# 7. スペース単位の機能ON・OFF

スペースごとに、挑戦状機能（質問・ミッションモード）全体をON・OFFできる。この全体ON・OFFは保持する。

保存先がスペース設定か Feature Flag かについては、実装設計時に現行構造との最小差分で決定する。本仕様書では断定しない。

## 7.1 ONの場合

* ナビゲーションに「挑戦状」を表示する
* 挑戦状ストーリーを表示する
* Pane内に質問・ミッションを設置できる
* スタンプカードを表示できる
* Hossiiを付与できる
* 自分の軌跡を表示できる

## 7.2 OFFの場合

* ナビゲーションの「挑戦状」を表示しない
* Pane内の質問・ミッションを表示しない
* スタンプカードを表示しない
* 新規回答を受け付けない
* 既存回答、達成記録、取得Hossiiは削除しない
* 管理者が再度ONにした場合は既存状態を復元する

OFFのスペースでは、参加者から見て質問・ミッションモード自体が存在しない状態にする。

---

# 8. 個別機能のON・OFF

最終仕様として、スペース全体がONの場合に以下を個別に設定できることを想定する。

* 挑戦状ナビゲーション
* Pane内の挑戦状設置
* スタンプカード
* Hossii付与
* Hossiiコレクションへの反映
* おみくじ
* 完了演出
* 他者回答一覧
* 自分の軌跡

個別機能をOFFにしても、既存データを削除しない。

### MVPでの扱い

* 個別機能9種類を、最初からすべてDBフラグ化しない
* MVPでは、スペース単位の全体ON・OFFと、ストーリー・項目単位の公開設定を中心に制御する
* 個別フラグの段階的追加は、必要になった時点で将来対応として行う

# 9. 挑戦状ストーリー

## 9.1 基本項目

管理者は以下を設定する。

| 項目         | 必須 | 内容              |
| ---------- | -: | --------------- |
| タイトル       | 必須 | 参加者向け名称         |
| 導入文        | 任意 | 目的やストーリー説明      |
| カバー画像      | 任意 | 一覧表示用画像         |
| 対象スペース     | 必須 | 配信先スペース         |
| 対象者        | 必須 | 全員、指定アカウント、管理者を除く参加者（指定グループは将来） |
| 公開状態       | 必須 | 下書き、公開、終了、アーカイブ |
| 公開開始日時     | 任意 | 表示開始日時          |
| 回答終了日時     | 任意 | 回答受付終了日時        |
| 進行方式       | 必須 | 自由順、順番固定        |
| 完了条件       | 必須 | 必須項目をすべて達成      |
| 完了メッセージ    | 任意 | 完了時の文章          |
| スタンプカード    | 必須 | ON・OFF          |
| Hossii付与   | 必須 | ON・OFF          |
| おみくじ       | 必須 | ON・OFF          |
| 完了限定Hossii | 任意 | 付与するHossii      |
| Pane設置     | 必須 | ON・OFF          |

## 9.2 複数ストーリー

1つのスペースに複数の挑戦状ストーリーを作成できる。

参加者が「挑戦状」を開くと、以下の区分で表示する。

* 進行中
* これから
* 完了
* 過去の挑戦状

## 9.3 対象者

対象者設定を、個別アカウントON・OFFより優先する正本とする。

### 最終仕様で選択できる対象

管理者は以下を選択できる。

* スペース参加者全員
* 指定アカウント
* 指定グループ（将来対応。現行にグループ実体が無いため MVP では提供しない）
* 管理者を除く参加者

さらに、個別アカウントを対象から除外できる。

対象外の参加者には、以下を表示しない。

* ストーリー
* 質問・ミッション
* スタンプカード

### MVPでの対象者

MVPでは、次のみを対象とする。

* スペース参加者全員
* 指定アカウント
* 管理者を除く参加者
* 個別アカウントの除外

「指定グループ」は将来対応とする。最終仕様からは削除しない。

発行参加IDでログインした認証ユーザーも、スペースに所属し対象者に含まれる場合は対象とする。

## 9.4 複製

管理者は既存ストーリーを複製できる。

複製するもの：

* 基本設定
* 質問・ミッション
* 回答形式
* 表示順
* Pane配置
* スタンプカード設定
* 完了設定

複製しないもの：

* 参加者の回答
* 達成記録
* 取得Hossii
* 参加者別進捗
* 専用URL・QRトークン

# 10. 質問・ミッション作成

管理者は、Googleフォームを作成するような流れで項目を追加する。

## 10.1 基本設定

各項目には以下を設定する。

| 項目       | 必須 | 内容               |
| -------- | -: | ---------------- |
| 種別       | 必須 | 質問、ミッション         |
| タイトル     | 必須 | 挑戦状の名称           |
| 説明       | 任意 | 詳細説明             |
| 設定理由     | 任意 | なぜ取り組むのか         |
| 回答形式     | 必須 | コメント、写真、3択、完了ボタン |
| 必須・任意    | 必須 | ストーリー完了条件に含むか    |
| 表示順      | 必須 | ストーリー内の順序        |
| 回答公開範囲   | 必須 | 5種類から選択          |
| 回答修正     | 必須 | 許可・不許可           |
| Pane設置   | 任意 | 設置先Pane          |
| 表示期間     | 任意 | 表示開始・終了          |
| Hossii付与 | 必須 | 付与する・しない         |

## 10.2 質問とミッションの表示

管理画面では「質問」「ミッション」を区別する。

参加者側では、どちらも「挑戦状」として統一して表示し、補助ラベルとして種別を表示できる。

# 11. 回答形式

初期実装では、以下の4形式を提供する。

## 11.1 コメント

参加者が文章を入力する。

設定可能項目：

* 一行／複数行
* プレースホルダー
* 最大文字数
* 最小文字数
* 必須／任意

## 11.2 写真

参加者が写真をアップロードする。

設定可能項目：

* 写真のみ
* 写真＋コメント
* 最大枚数
* ファイルサイズ上限
* 必須／任意

初期実装では最大3枚を上限とする。

## 11.3 3択

管理者が3つの選択肢を設定し、参加者が1つを選択する。

設定可能項目：

* 選択肢1
* 選択肢2
* 選択肢3
* 回答後コメント
* 正解の有無

初期実装では単一選択とする。

## 11.4 完了ボタン

参加者が行動後に完了操作を行う。

設定可能項目：

* ボタン文言
* 確認メッセージ
* 完了後コメント
* 完了後写真
* 自己申告
* 管理者承認

---

# 12. 達成条件

以下のいずれかで達成とする。

* 有効なコメント回答を保存した
* 必須写真を保存した
* 3択を選択して保存した
* 完了ボタンを押した
* 管理者承認が必要な場合、承認された

未入力、アップロード失敗、保存失敗の場合は達成としない。

---

# 13. 必須項目と任意項目

## 13.1 必須項目

すべての必須項目を達成すると、挑戦状ストーリーを完了とする。

## 13.2 任意項目

任意項目はストーリーの完了条件に含めない。

ただし、任意項目を達成した場合もHossiiを付与する。

例：

* 必須5項目を達成：ストーリー完了
* 任意2項目も達成：追加でHossiiを2体取得

# 14. スタンプカード

## 14.1 カード生成

以下をすべて満たした時点で、対象参加者にスタンプカードを表示する。

1. スペースの質問・ミッションモードがON
2. ストーリーが公開済み
3. 公開中の質問・ミッションが1つ以上ある
4. 参加者が対象者に含まれる
5. 参加者がログイン済み
6. スタンプカード設定がON

## 14.2 スタンプ数

**1つの質問・ミッション達成につき、1つのスタンプ枠を埋める。**

スタンプカードの枠数は、Hossii付与対象となる公開項目数から自動生成する。

5、10、30、50は固定カード数ではなく、ストーリー作成テンプレートとして扱う。

テンプレート例：

* 5つの挑戦状
* 10の挑戦状
* 30日チャレンジ
* 50の挑戦
* 空の状態から作成

## 14.3 自動配置

項目数に応じて、スタンプ配置テンプレートを自動選択する。

* 1〜5個：大きめの自由配置
* 6〜10個：2〜3列
* 11〜20個：グリッドまたは軌跡型
* 21〜30個：道、星座、足跡型
* 31〜50個：複数ページまたは区画分割

管理者は配置テンプレートを変更できる。

MVPでは、スタンプごとの自由座標編集は行わない。

## 14.4 カード表示内容

* ストーリー名
* 達成数／総数
* 必須項目の進捗
* 任意項目の進捗
* 取得済みHossii
* 未取得枠
* 開始日
* 最終更新日
* 完了状態

# 15. Hossiiスタンプ

## 15.1 基本付与ルール

質問・ミッションを達成すると、Hossiiスタンプを1体付与する。

以下の順序で抽選する。

1. 対象となるHossiiプールを決定する
2. 未取得Hossiiを優先する
3. レアリティを抽選する
4. 該当レアリティ内の未取得Hossiiから抽選する
5. 未取得が存在しない場合は重複を許可する
6. 抽選結果を永続保存する

## 15.2 重複

* アカウント全体で未取得Hossiiを優先する
* 同一ストーリー内では可能な限り重複させない
* 取得可能な未取得Hossiiがない場合は重複を許可する
* 同じHossiiを複数取得した場合は、取得回数を表示する

## 15.3 結果の固定

一度付与されたHossiiは、以下によって変化しない。

* 再読み込み
* 再ログイン
* 回答修正
* 表示順変更
* ストーリー終了

同じ達成に対する再抽選は行わない。

# 16. Hossiiレアリティ

レアリティは以下の4段階とする。

| 内部名称       | 参加者向け名称       |
| ---------- | ------------- |
| normal     | いつものHossii    |
| rare       | ちょっと珍しいHossii |
| super_rare | とても珍しいHossii  |
| secret     | 特別なHossii     |

## 16.1 基本確率

初期確率を以下とする。

| レアリティ         | 基本確率 |
| ------------- | ---: |
| いつものHossii    |  80% |
| ちょっと珍しいHossii |  16% |
| とても珍しいHossii  | 3.5% |
| 特別なHossii     | 0.5% |

確率の合計は100%とする。

## 16.2 確率管理

抽選確率はスーパー管理者が管理する。

スペース管理者は確率を変更できない。

ストーリーごとに取得対象Hossiiを限定することはできる。

---

# 17. 達成によるレア確率上昇

同じ挑戦状ストーリー内で項目を達成するほど、レア以上の取得確率を上昇させる。

## 17.1 上昇ルール

ストーリー内の達成数に応じて、レア以上の確率へ補正を加える。

| ストーリー内達成数 | レア以上への補正 |
| --------: | -------: |
|       1〜2 |     補正なし |
|       3〜4 |   ＋2ポイント |
|       5〜9 |   ＋4ポイント |
|     10〜19 |   ＋7ポイント |
|      20以上 |  ＋10ポイント |

補正分は「いつものHossii」の確率から差し引く。

レア、スーパーレア、シークレットへの配分比率は、スーパー管理者設定に従う。

## 17.2 天井

レア以上を8回連続で取得できなかった場合、9回目はレア以上を確定する。

スーパーレアまたはシークレットを20回連続で取得できなかった場合、21回目はスーパーレア以上の確率を大きく上げる。ただし確定とはしない。

レア以上を取得した時点で、レア天井カウントをリセットする。

## 17.3 完了限定Hossii

ストーリーのすべての必須項目を達成した場合、通常抽選とは別に完了限定Hossiiを1体付与する。

完了限定Hossiiは重複抽選ではなく、ストーリーに設定されたHossiiを確定付与する。

# 18. おみくじ

## 18.1 概要

Hossii取得時に、Hossiiからの短い言葉としておみくじを付与する。

おみくじは参加者への評価ではない。

## 18.2 結果と確率

| 結果 |  確率 |
| -- | --: |
| 大吉 |  8% |
| 中吉 | 17% |
| 吉  | 30% |
| 小吉 | 22% |
| 末吉 | 20% |
| 凶  |  3% |

## 18.3 Hossiiとの関係

Hossiiのレアリティとおみくじ結果は別々に抽選する。

ノーマルHossiiでも大吉になることがあり、特別なHossiiでも末吉になることがある。

レアリティを人の価値や成果の良し悪しと結びつけない。

## 18.4 おみくじメッセージ

基本メッセージはHossii共通テンプレートとして、スーパー管理者が管理する。

スペース管理者は、挑戦状ストーリー固有の追加メッセージを設定できる。

表示例：

> 大吉！
> 新しい一歩が、次の出会いにつながりそう。
> 今日の好奇心を大切にしてみよう。

## 18.5 凶の表現

凶であっても、不安をあおる表現、失敗を断定する表現、人格を否定する表現は禁止する。

例：

> 今日は少し立ち止まる日かも。
> 焦らず、自分のペースで進もう。

## 18.6 結果の固定

おみくじはHossii付与時に1回のみ抽選し、再抽選しない。

# 20. 回答公開範囲

管理者は、質問・ミッションごとに以下の5種類から選択する。

5種類は最終仕様としてすべて保持する。最終仕様から削除しない。

## 20.1 自分だけ

回答者本人のみ閲覧できる。

通常のスペース管理者は閲覧できない。

通常のスーパー管理画面からも閲覧できないことを基本仕様とする。

監査記録を残した特別アクセスは、現行実装に存在しない。したがって次のとおり扱う。

* 今回のMVP対象外
* 将来、別仕様として検討する
* 現時点では、特別アクセスが存在する前提にしない

法令対応や重大な安全上の問題への対応が必要になった場合は、別仕様で設計する。

## 20.2 管理者だけ

回答者本人と、対象スペースの管理者が閲覧できる。

## 20.3 回答後にみんなで共有

参加者は、自分が回答した後に、他の参加者の回答を閲覧できる。

回答前は他者回答を閲覧できない。

## 20.4 最初からみんなに公開

参加者は回答前から、他の参加者が公開した回答を閲覧できる。

## 20.5 匿名で共有

参加者間では回答者名を表示しない。

スペース管理者には回答者名を表示する。

参加者向け回答画面には、以下を明示する。

> 他の参加者には匿名で共有されます。管理者には回答者が表示されます。

## 20.6 初期値

新規質問・ミッションの初期値は、**管理者だけ**とする。

管理者が明示的に公開範囲を変更しない限り、参加者間で共有しない。

## 20.7 公開範囲の拡大

回答が1件以上存在する場合、管理者は既存回答の公開範囲を一方的に広げられない。

公開範囲を広げる場合は、新しい質問・ミッションまたは新しい版を作成する。

## 20.8 公開範囲の保護方針とMVP実装順

最終的には、5種類すべてをDB・RLS（または同等のサーバ側権限）で保護する。

フロント上の非表示だけで公開範囲を実現してはならない。

### MVP実装順

* 最初の回答実装では、「自分だけ」「管理者だけ」の2種類を先行してよい
* 残り3種類（回答後にみんなで共有、最初からみんなに公開、匿名で共有）は後続PRで追加してよい
* 先行実装中も、最終仕様の5種類は維持し、UI・データモデルに拡張余地を残す

# 22. Paneへの設置

## 22.1 設置エリア

各Paneに「挑戦状設置エリア」を持たせる。

管理者はPaneごとに以下を設定する。

* 設置する質問・ミッション
* 表示順
* 表示数
* 表示開始日時
* 表示終了日時
* 表示デザイン

## 22.2 表示方式

質問・ミッションは、通常投稿と異なる「目立つ吹き出し」として自動配置する。

## 22.3 配置ルール

* 管理者が表示順を設定する
* 座標はシステムが自動決定する
* 画面外へ配置しない
* 背景変更後も破綻しない
* スマートフォンで押しやすい
* 通常のHossiiや吹き出しと過度に重ならない
* 未回答、回答済み、ロック中を見た目で区別する

MVPでは自由座標を使用しない。自動配置と表示順を使用する。

## 22.4 複数Paneへの設置

同一の挑戦状項目を複数Paneへ設置できる。

どのPaneに設置しても、回答・達成は共通とする。

Paneごとに別回答・別報酬を作らない。

設置場所と表示順は、挑戦状項目・回答・達成の正本から分離して保持する。

保存方式を JSON（例: Pane設定やストーリー側の参照一覧）にするか、専用配置テーブルにするかは、実装設計時に決定する。本仕様書では断定しない。

# 23. 公開後の編集

## 23.1 公開前

以下を自由に変更できる。

* 項目追加
* 項目削除
* 順番変更
* 回答形式変更
* 選択肢変更
* 公開範囲変更
* スタンプ設定変更
* Pane配置変更

## 23.2 公開後・回答者なし

警告を表示したうえで、構造を変更できる。

## 23.3 公開後・回答者あり

以下のみ変更できる。

* 誤字脱字
* 説明文
* 補足
* 参考画像
* 期限延長
* 意味を変えない軽微な文言

以下は変更できない。

* 回答形式
* 選択肢の意味
* 達成条件
* 必須・任意
* 回答済み項目の削除
* 公開範囲の拡大
* Hossii付与の有無
* 既存回答との対応を崩す変更

## 23.4 項目追加

回答が1件以上存在する公開中ストーリーには、新しい項目を追加できない。

新しい項目を追加する場合は、以下のいずれかとする。

* 新しいストーリーを作る
* 新しい版を作る
* 別の追加ストーリーとして公開する

## 23.5 新しい版

大きく変更する場合は、既存ストーリーを複製して新しい版を作る。

* 旧版の回答を引き継がない
* 旧版の達成履歴を保持する
* 旧版の取得Hossiiを保持する
* 旧版をアーカイブできる

# 24. 回答修正・削除

## 24.1 回答修正

管理者設定で回答修正が許可されている場合、参加者はストーリー完了後も回答を修正できる。

理由は、学びや振り返りを後から書き足せるようにするためである。

回答修正によって以下は行わない。

* Hossiiの再抽選
* おみくじの再抽選
* スタンプの追加付与

管理者承認型の場合、内容を大きく修正した場合は再承認待ちとする。

## 24.2 参加者による回答削除

参加者が回答を削除した場合でも、取得済みHossiiは原則として保持する。

Hossiiは、一度取り組んだ軌跡として扱う。

ただし、回答データには削除済みであることを記録し、軌跡画面では削除済みとして表示するか非表示にする。

## 24.3 管理者による達成取消

誤操作、不正、重複処理などの理由で管理者が達成を取り消した場合は、対応するHossiiを回収できる。

回収時には以下を記録する。

* 取消者
* 取消日時
* 取消理由
* 対象Hossii
* 元の達成記録

参加者が通常の回答修正をしただけでは、Hossiiを回収しない。

---

# 25. 通常投稿との関係

質問・ミッションへの回答は専用回答データを正本とする。

既存の通常投稿データ（吹き出し投稿）を、回答の正本として使用しない。

回答者は、公開範囲に反しない場合に限り、回答を通常の吹き出し投稿として共有できる。

共有投稿は回答の複製表示であり、正本ではない。

以下を不変条件とする。

* 共有投稿を削除しても元回答は残る
* 元回答を修正しても共有投稿を自動上書きしない
* 元回答削除時は共有投稿の扱いを確認する
* 匿名回答は匿名のまま共有する
* 「自分だけ」「管理者だけ」の回答は通常投稿へ共有できない

# 26. ストーリー完了

## 26.1 完了条件

## 26.2 完了時の表示

* おめでとうメッセージ
* ストーリー名
* 達成した必須項目数
* 達成した任意項目数
* 集めたHossii
* 完了限定Hossii
* 開始日
* 完了日
* 自分の軌跡を見るボタン

## 26.3 完了限定Hossii

完了時に、ストーリーごとに設定された限定Hossiiを1体付与する。

同じ参加者が同じストーリーを再度完了扱いになっても、完了限定Hossiiは重複付与しない。

# 29. 正本

以下をデータ上の正本とする。

* ストーリー内容：挑戦状ストーリー専用データ
* 質問・ミッション内容：挑戦状項目専用データ
* 参加者の回答：専用回答データ（既存の通常投稿データは使用しない）
* 達成状態：達成専用データ
* 管理者承認：承認データ
* 取得Hossii：報酬付与専用データ（抽選結果は付与時に永続保存する）
* おみくじ：報酬付与時のおみくじ結果（付与時に永続保存する）
* スタンプカード：達成・報酬付与履歴から導出する（専用の別進捗を正本にしない）
* Hossiiコレクション：アカウント全体の報酬付与履歴から導出する（マイHossii見た目設定は正本にしない）
* 自分の軌跡：回答・達成・報酬データから導出
* 通常投稿：回答者が任意で共有するための派生表示であり、回答の正本ではない
* Pane設置：設置場所・表示順は項目／回答／達成の正本から分離して保持する

挑戦状ストーリー、項目、回答、達成、報酬には専用データ基盤を設ける。

具体的なテーブル名・列名は次のDB設計タスクで確定する。本仕様では仮称（`challenge_program` 等）に留める。

既存の `#card` スタンプ機能とは別機能とし、正本・進捗・UIを共有しない。

# 30. 不変条件

以下は、他機能の変更によって意図せず変化してはならない。

1. 同一参加者・同一項目へ、許可されていない重複Hossii付与をしない
2. 一度付与したHossiiを再表示時に変更しない
3. 一度確定したおみくじを再抽選しない
4. 他者の回答を自分の回答として表示しない
5. 対象外参加者にストーリーを表示しない
6. 非公開回答を権限のない参加者へ表示しない
7. 「自分だけ」の回答を通常の管理者へ表示しない
8. 回答済みストーリーの構造を後から変更しない
9. 項目の表示順変更で回答との対応を崩さない
10. 機能OFFで既存回答・Hossiiを削除しない
11. 通常投稿の削除で元回答を失わない
12. スタンプカードの表示数と付与対象項目数を矛盾させない
13. 同じ完了限定Hossiiを同一ストーリーで複数回付与しない
14. スペース管理者が権限のないスペースの回答を閲覧できない
15. 参加者の回答公開範囲を、回答後に一方的に広げない
16. 回答修正でHossiiやおみくじを再抽選しない
17. 同じ質問を複数Paneへ設置しても達成データを重複作成しない
18. Hossiiコレクションはスペース退会後もアカウントに保持する

# 31. 必須回帰テスト

## 31.1 権限

* スーパー管理者が必要な管理機能を利用できる
* スペース管理者が管理スペースのみ編集できる
* 一般参加者が管理画面へ入れない
* 対象外参加者がストーリーへ入れない
* 「自分だけ」の回答が通常管理者に表示されない

## 31.2 スペース設定

* 機能ONでナビゲーションと挑戦状が表示される
* 機能OFFで挑戦状機能が完全に非表示になる
* OFFにしても既存データが削除されない
* 再度ONにすると既存進捗が復元される

## 31.3 回答

* コメントを保存できる
* 写真を保存できる
* 3択を保存できる
* 完了ボタンで達成できる
* 必須入力不足では達成しない
* 回答修正設定が反映される
* 完了後も許可されていれば修正できる

## 31.4 公開範囲

* 自分だけ
* 管理者だけ
* 回答後に共有
* 最初から公開
* 匿名共有

の各設定が正しく反映される。

匿名回答は参加者には匿名、管理者には記名で表示される。

## 31.5 Hossii付与

* 達成時に1回だけ付与される
* 二重送信でも重複付与されない
* 未取得Hossiiが優先される
* 再読み込みしても同じHossiiが表示される
* 回答修正で再抽選されない
* 管理者取消時に回収できる
* 回収履歴が残る

## 31.6 レア確率

* 達成数に応じて確率補正が適用される
* 確率の合計が100%になる
* 8回連続でレア以上が出ない場合、9回目にレア以上が出る
* レア取得時に天井カウントがリセットされる

## 31.7 おみくじ

* Hossii付与時に1回だけ抽選される
* 再表示時に結果が変わらない
* 確率合計が100%になる
* 凶でも否定的・危険な文言を表示しない

## 31.8 スタンプカード

* 項目数に応じて枠数が自動生成される
* 必須項目と任意項目を区別できる
* 達成数と表示が一致する
* 31個以上で複数ページまたは区画表示になる
* 同じ項目の複数Pane設置でスタンプが重複しない

## 31.9 完了

* 必須項目をすべて達成すると完了になる
* 任意項目未達でも完了できる
* 完了限定Hossiiが1回だけ付与される
* 完了演出が表示される
* 軌跡画面へ移動できる

## 31.10 公開後編集

* 回答があるストーリーの構造を変更できない
* 回答済み項目を削除できない
* 公開範囲を広げられない
* 新しい版では旧版の回答を引き継がない
* 旧版の回答とHossiiが保持される

# 35. 既存機能との区別

本機能は既存機能を流用・拡張するが、正本を重複させない。

| 既存機能 | 挑戦状との関係 |
| --- | --- |
| 通常投稿・吹き出し | 回答の任意共有先。回答正本ではない |
| `#card` スタンプ | 投稿数ベースの既存機能。挑戦状スタンプとは別。正本・進捗・UIを共有しない |
| マイHossii | Hossiiの見た目設定。コレクションの正本ではない |
| Hossiiガイド吹き出し | 案内・問いかけUI。回答・達成・報酬基盤とは別 |
| Pane | 挑戦状の設置先として流用する |
| 写真Storage | 回答写真で既存方式を拡張して流用する予定 |
| 権限ヘルパ | 現行のスペース管理可否判定を流用する予定 |

# Hossiiからの挑戦状

## 画面モックアップ構成書

> **対象機能:** 質問・ミッション・スタンプカード
> **ステータス:** UI・UX構成 暫定確定
> **対象端末:** スマートフォン優先、PC対応
> **参加者向け画面:** 5画面

# 1. UI設計原則

本機能は、管理・課題提出の印象よりも、Hossiiから問いや挑戦が届き、楽しみながら一歩ずつ進む体験を重視する。

## 1.1 参加者側

* 「やらなければならない」より「やってみたい」と感じられる
* 未達成を責める表現を使わない
* 現在地と次の一歩が分かる
* 回答前に公開範囲が分かる
* 回答後すぐにHossii獲得の喜びを感じられる
* 自分の回答と軌跡へ迷わず戻れる
* Hossiiの表情やコレクションを楽しめる
* 画面を情報で埋めすぎない
* 主要操作は片手で押しやすい位置に置く

## 1.2 管理者側

* Googleフォームを作成する程度の感覚で設定できる
* ストーリー全体と質問単位の設定を混同させない
* 公開前と公開後の状態を明確に分ける
* 誰に、どこで、何が見えるか確認できる
* 公開後に変更できない項目を事前に知らせる
* 回答、達成、公開範囲を安全に管理できる
* 高機能でも、一画面に設定を詰め込みすぎない

# 16. モックアップで検証する事項

ビジュアルモックアップ作成後、以下を確認する。

## 16.1 参加者体験

* 「挑戦状」の意味が初見で伝わるか
* 次に何をすればよいか分かるか
* 質問とミッションの違いが伝わるか
* 公開範囲を回答前に理解できるか
* スタンプカードが子ども向けに見えすぎないか
* Hossii獲得演出が過剰でないか
* レアリティが人の評価に見えないか
* 任意項目が本当に任意だと伝わるか
* 自分の軌跡を見返したくなるか

## 16.2 管理者体験

* ストーリーと個別質問の設定を区別できるか
* Googleフォームに近い感覚で項目を追加できるか
* 公開範囲の違いを理解できるか
* 公開後に変更できない項目が分かるか
* Paneへの設置方法が直感的か
* スタンプ数が自動生成されることを理解できるか
* 回答一覧と進捗管理を混同しないか
* 「自分だけ」の回答が見えないことを理解できるか

# 17. デザイン方向

## 17.1 共通

* ぷくっとした立体感
* シンプルで明るい
* 子どもっぽすぎない
* 大人も使える綺麗さ
* Hossiiの表情が主役
* 青空、星、光、軌跡を補助モチーフにする
* 文字や設定項目を装飾で埋めすぎない

## 17.2 参加者側

* 柔らかいカード
* 大きめの余白
* Hossiiの表情を感情的な報酬として使う
* 未達成枠は灰色にせず、淡い光やシルエットで表現
* 完了時のみ少し華やかにする

## 17.3 管理者側

* 参加者画面より装飾を抑える
